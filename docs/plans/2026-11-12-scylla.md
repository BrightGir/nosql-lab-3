# Lab 3 ScyllaDB Implementation Plan

**Goal:** Extend Lab 2 for variant 7809 while preserving CouchDB and Etcd APIs.

**Architecture:** Independent business-operation audit events in three denormalized daily UTC partitions. Existing storage remains authoritative. ScyllaDB uses RF=3, writes ONE and reads QUORUM. Keyset pagination traverses days in chronological order.

**Tech Stack:** Java 17, Spring Boot, Scylla Java driver, Compose, Python experiments.

1. Copy Lab 2 source and regression tests into the empty lab3 workspace; leave lab2 intact.
2. Add integration tests for automatic business-event capture, result/operation/entity queries, ordering, daily boundaries, pagination, invalid cursors and storage failure isolation. Observe failure before implementation.
3. Add schema, cluster configuration, query service, event capture and API. Verify old and new tests.
4. Run three-node cluster; execute regression and integration scenarios.
5. Measure ONE/QUORUM versus other consistency pairs with all replicas and one stopped, restore in finally.
6. Observe tombstones in an isolated experimental table before deletion, after deletion and after repair/grace/compaction.
7. Measure throughput, mean and p95 with a concurrent workload; retain raw observations and environment details.
8. Write README and report with actual results and limitations. Verify all claims against saved evidence.

Design alternatives: a single table cannot support the three queries without filtering; materialized views obscure explicit query design. Use three application-maintained tables in a logged batch (eventual cross-partition completion, no cross-store transaction). Capture at the HTTP business-operation boundary, preserving old response semantics on audit failure and exposing/logging audit failures. This lab implementation does not guarantee durable delivery during a total Scylla outage.
